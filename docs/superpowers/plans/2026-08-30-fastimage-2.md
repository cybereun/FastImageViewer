# FastImage 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade FastImage from a folder viewer into a reliable local-first image browser, organizer, batch file tool, and lightweight editor, then document and publish the verified Windows portable build.

**Architecture:** Keep the Electron desktop monolith, but introduce a lightweight hexagonal boundary: pure image/selection rules in `src/domain`, application orchestration in hooks/services, and filesystem/preferences/thumbnail behavior behind the Electron preload adapter. React components remain focused on presentation and user interaction. No backend or cloud service is introduced.

**Tech Stack:** Electron, React 19, TypeScript, Vite, Tailwind CSS, native Electron filesystem IPC, Canvas API, Vitest.

**Spec:** User request in the current task and the improvement proposal recorded in the preceding conversation; release notes and version history live in `README.md` and `CHANGELOG.md`.

## Global Constraints

- Work only in `L:\Codex-L\fast-image`; keep the original Y: drive checkout unchanged until the final sync.
- Preserve `nodeIntegration: false`, `contextIsolation: true`, and `webSecurity: true`.
- Never delete source files permanently from the application; use the Windows Recycle Bin for user-initiated deletion.
- Validate filesystem IPC arguments in the Electron main process and expose only narrow preload methods.
- Support Windows 10/11 and produce a portable Windows executable.
- Every completed feature must have either a pure unit test or a documented manual verification path.
- Do not claim release/build success without a fresh verification command and exit code.
